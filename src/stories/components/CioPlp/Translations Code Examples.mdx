# Translations (i18n)

The translations feature allows you to customize all UI text strings in the PLP to support internationalization (i18n).
All translation keys are optional - any non-provided translation will fallback to English defaults.

> **Important Note:** Translations only apply to hardcoded UI strings within the library (e.g., "results", "Filters", "Sort by:", etc.).
> They do **not** translate dynamic content from the API response, such as:
> - Sort option labels (e.g., "Relevance", "Price: Low to High")
> - Facet names and values (e.g., "Color", "Size", "Brand")
> - Product names, descriptions, and other catalog data
>
> API response content should be translated on your backend or through Constructor.io's dashboard configuration.

## Available Translation Keys

All keys are optional. Here are the translatable strings:

```typescript
{
  // Result display
  "results": "results",
  "for": "for",

  // Filters
  "Filters": "Filters",

  // Sort
  "Sort by:": "Sort by:",
  "By": "By",
  "Sort": "Sort",

  // Range Filter
  "from": "from",
  "to": "to",

  // Groups/Categories
  "Categories": "Categories",
  "Show All": "Show All",
  "Show Less": "Show Less",

  // Product Card
  "Add to Cart": "Add to Cart",

  // Screen reader announcements (live region)
  // {count} is replaced with the number of results
  "Loading results": "Loading results",
  "No results found": "No results found",
  "1 result found": "1 result found",
  "{count} results found": "{count} results found",

  // Zero Results
  "Sorry, we didn't find:": "Sorry, we didn't find:",
  "Sorry, we were unable to find what you were looking for.": "Sorry, we were unable to find what you were looking for.",
  "Check for typos": "Check for typos",
  "Use fewer keywords": "Use fewer keywords",
  "Broaden your search terms": "Broaden your search terms"
}
```

## Basic Usage

```jsx
import { CioPlp } from "@constructor-io/constructorio-ui-plp";
import "@constructor-io/constructorio-ui-plp/styles.css";

const DEMO_API_KEY = "key_M57QS8SMPdLdLx4x";

export default function MyComponent() {
  return (
    <CioPlp
      apiKey={DEMO_API_KEY}
      translations={{
        results: 'resultados',
        for: 'para',
        Filters: 'Filtros',
        'Sort by:': 'Ordenar por:',
        By: 'Por',
        Sort: 'Ordenar',
        from: 'desde',
        to: 'hasta',
        Categories: 'Categorias',
        'Show All': 'Mostrar todo',
        'Show Less': 'Mostrar menos',
        'Add to Cart': 'Agregar al carrito',
        "Sorry, we didn't find:": 'Lo sentimos, no encontramos:',
        'Sorry, we were unable to find what you were looking for.':
          'Lo sentimos, no pudimos encontrar lo que buscabas.',
        'Check for typos': 'Revisa errores tipograficos',
        'Use fewer keywords': 'Usa menos palabras clave',
        'Broaden your search terms': 'Amplia tus terminos de busqueda',
        'Loading results': 'Cargando resultados',
        'No results found': 'No se encontraron resultados',
        '1 result found': '1 resultado encontrado',
        '{count} results found': '{count} resultados encontrados',
      }}
    />
  );
}
```


## Screen Reader Announcements

The `Loading results`, `No results found`, `1 result found` and `{count} results found` keys
are not rendered visually. They populate a live region (`role="status"`) that announces result
updates to screen reader users when filters, sort or pagination change, since those updates
do not move focus.

`{count}` is replaced with the number of results, so it can be placed wherever the target
language needs it — for example `'{count} resultados encontrados'`. A separate singular key
is provided since `1 results found` is incorrect in most languages.

Results are also announced on page load, since the default URL helpers reload the page on
every filter, sort or pagination change and that load is the only one that follows the user's
action.
